# 股票/ETF 永续合约监控器（OKX 数据源）

监控 **OKX 上架的所有股票/ETF 永续合约**（`TSLA-USDT-SWAP`、`NVDA-USDT-SWAP`、`QQQ-USDT-SWAP` 等，约 227 个标的），覆盖美股**盘前 / 盘中 / 盘后**，按「24h 涨跌幅」和「24h 振幅」超阈值发邮件到你的 QQ 邮箱。

> **为什么用 OKX 而不是币安？** 币安合约 API（`fapi.binance.com`）会屏蔽美国 IP（HTTP 451），而 GitHub Actions 服务器在美国。OKX 的股票/ETF 永续与币安高度重叠（都是美股大盘股 + 热门 ETF），且 OKX 公开行情接口从美国可正常访问、无需任何 key。

- **标的自动更新**：脚本从 OKX `instruments` 接口动态筛出 `instCategory=3`（股票/ETF）的永续合约，交易所上新自动覆盖，无需手动维护名单。
- **无需任何 API key**：OKX 公开行情接口，连注册都省了。
- **一次调用拿全量**：`tickers` 接口一次返回所有合约行情，比逐个查询高效得多。
- **24 小时运行**：跑在 GitHub 云服务器，你电脑关不关机都行。

## 一、文件结构

| 文件 | 作用 |
|------|------|
| `monitor.py` | 核心脚本（筛合约、取行情、判阈值、发邮件） |
| `config.json` | 阈值、宽基 ETF 列表、收件人 |
| `.github/workflows/monitor.yml` | 定时运行（盘前5分钟/盘后10分钟/盘中15分钟） |
| `state/` | 冷却状态（自动生成，别删） |

## 二、监控规则（默认参数）

| 对象 | 涨跌幅阈值 | 振幅阈值 |
|------|-----------|---------|
| 宽基 ETF（QQQ、SPY） | ±1.3% | — |
| 个股 | ±3% | ≥5% |

- **涨跌幅** = 现价相对 24h 前价格（`(last - open24h) / open24h`）
- **振幅** = 24h 最高 − 最低，相对 24h 前价格
- **冷却**：同一标的触发后 60 分钟内不重复告警

## 三、时段频率（美东时间，自动适配夏令时）

| 时段 | 美东时间 | 北京对应 | 频率 |
|------|---------|---------|------|
| 盘前 | 4:00–9:30 | 17:00–22:30 | 每 5 分钟 |
| 盘中 | 9:30–16:00 | 22:30–次日5:00 | 每 15 分钟 |
| 盘后 | 16:00–20:00 | 5:00–9:00 | 每 10 分钟 |

## 四、配置发信密钥（唯一需要手动做的）

监控器已经部署到 GitHub 并跑通取价逻辑，只差 QQ 邮箱授权码用于发信：

1. GitHub 仓库 `Settings` → `Secrets and variables` → `Actions` → 添加：
   - `SMTP_USER`（已配置，无需再动）= `2494994336@qq.com`
   - `SMTP_PASSWORD` = QQ 邮箱授权码（16 位，去 mail.qq.com → 设置 → 账户 → 开启 POP3/SMTP 服务获取）
2. 配好后触发一次测试即可收信。

> 如果你之前的 `bianca-monitor` 项目用过 QQ 邮箱授权码，可以直接用同一个（注意：授权码在 QQ 邮箱里只显示一次，忘了需要重新生成）。

## 六、手动自检（可选）

在 `Actions` 页 `Run workflow` 时，运行模式选 `check`，会打印当前波动最大的前 40 个标的（忽略时段/节流，强制取价）。

## 七、常见问题

**Q：需要注册 API key 吗？**
不需要。OKX 公开行情接口无需 key，脚本只用 Python 标准库。

**Q：OKX 上新股票/ETF 合约会自动监控吗？**
会。每次运行都重新拉最新合约列表（约 227 个，随交易所上新动态变化）。

**Q：想改阈值 / 加宽基 ETF？**
改 `config.json`：阈值在 `thresholds`，宽基 ETF 在 `index_symbols`（用 ±1.3% 阈值的那几个）。

**Q：怎么停止？**
删仓库，或 `Actions` 页 `Disable workflow`。
